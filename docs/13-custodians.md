# Хранители корневого ключа: компьютер без сети

Корневой ключ подписывает справочник ключей (кто может подписывать) и политику
(какие события и какой кворум). Он не подписывает приказы и в момент ЧС не нужен.
Хранится на отдельном компьютере, который никогда не подключается к сети, и
открывается только двумя хранителями вместе. Решение — ADR 0013.

```
 Устройство человека        Панель (дежурный, в сети)        Компьютер хранителей (без сети)
 ключ человека ──публичный──▶ «Справочник и ключи»            окно хранителей
                  ключ       заявка.json ──── носитель ────▶  проверка + подпись (2 пароля)
                             ответ.json  ◀─── носитель ─────  ответ.json
                             «Ответ хранителей» → публикация
```

## 1. Подготовка компьютера (один раз)

1. Любой ноутбук. Wi-Fi и Bluetooth отключить в BIOS/UEFI, сетевой кабель не
   подключать никогда. Диск — с полным шифрованием.
2. На машине с интернетом собрать комплект: `./scripts/custodian-kit.sh`
   (для Windows: `./scripts/custodian-kit.sh win_amd64 3.12`). Перенести каталог
   `custodian-kit/` на носитель.
3. На ноутбуке (нужен Python 3.11+):
   `python -m pip install --no-index --find-links custodian-kit alerting`
4. Запуск: `alerting-custodian --vault <путь>/root-vault.json`, затем открыть в браузере
   этого ноутбука **http://127.0.0.1:7090**.

## 2. Создание корневого ключа (один раз, вдвоём)

В окне хранителей: идентификатор организации (как `ALERTING_ORG` на сервере), затем
**каждый хранитель сам** вводит своё ФИО и пароль (не короче 12 символов). Ключ
откроется только при обоих паролях; по одному паролю его не подобрать.

Сразу после создания:

- **«Напечатать карточку»** — отпечаток и открытый ключ. Экземпляры — каждому
  хранителю и администратору сервера: по карточке сверяют ключ при переносе.
- **«Скачать резервную копию»** — на второй носитель, во второй сейф. Она зашифрована
  и без обоих паролей бесполезна.
- Каждый хранитель запечатывает свой пароль в конверт и кладёт в свой сейф. Потеря
  любого из двух паролей — потеря ключа: тогда организацию переводят на новый ключ
  (раздел 4) и всех людей переносят в нём без перерегистрации.

## 3. Обычный сеанс: заявка → ответ

1. Дежурный в панели («Справочник и ключи») собирает изменения: новые люди (их
   публичные ключи — с экрана регистрации устройства), вывод и отзыв ключей, ключ
   отзыва смены, кодовая книга. Нажимает «Скачать заявку» и несёт файл на носителе.
2. Хранители вдвоём открывают окно хранителей и выбирают файл заявки. Окно **сначала
   проверяет**, что справочник в заявке подписан этим корневым ключом: подменённый по
   дороге файл будет отвергнут.
3. На экране — каждое изменение полностью. Идентификатор каждого нового ключа
   сверяют с тем, что показало устройство человека (или со слов человека по телефону
   с обратным звонком).
4. Оба пароля, отметка «Мы вдвоём проверили каждое изменение», «Подписать». Файл
   ответа сохраняется — на тот же носитель.
5. Дежурный в панели: «Ответ хранителей» → выбрать файл. Сервер проверяет подпись
   корня и рост версии и публикует; человек сразу может войти.

Ключ открывается только на одну подпись и сразу выбрасывается из памяти. На диск
не пишется ничего, кроме зашифрованного файла ключа.

## 4. Перенос организации на этот ключ

Когда корневой ключ раньше лежал на сервере (демо-стенд) или пароль утерян:

1. На новом компьютере хранителей создать ключ (раздел 2).
2. Дежурный готовит обычную заявку (например, «внести ключ отзыва смены» и «убрать
   ключ отзыва стенда»). В ней справочник подписан прежним ключом.
3. Окно хранителей покажет красную плашку **«ПЕРЕНОС ОРГАНИЗАЦИИ»** с отпечатком
   прежнего ключа. Подписывать — только если перенос решён. Отметить «Подтверждаем
   перенос», подписать.
4. Администратор сервера: `./docker/rotate-root.sh ответ-….json` — скрипт покажет
   отпечаток и попросит **ввести его с карточки**, затем переключит сервер,
   закреплённый ключ и удалит демо-ключи с сервера. Люди и их ключи сохраняются.

Это единственный шаг не через интерфейс: он меняет, чему доверяет сервер, и поэтому
доступен только тому, кто управляет самим сервером.

## 5. Когда нужен этот компьютер

| Действие | Корневой ключ |
|---|---|
| Приказ, отбой | не нужен |
| Отзыв украденного телефона | не нужен — «Отозвать сейчас» ключом отзыва смены |
| Новый человек или устройство, увольнение | заявка |
| Кодовая книга, кворум, продление политики (раз в год) | заявка |
| Ключ отзыва смены: внести, сменить, убрать | заявка |

Раз в год — учение: открыть окно, ввести оба пароля в «проверке» (без подписи),
убедиться, что резервная копия восстанавливается на втором компьютере.
