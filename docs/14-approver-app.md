# Приложение ЛПР: сборка, регистрация, работа

Почему оно устроено так — [ADR 0016](adr/0016-native-approver-app.md). Здесь — как его
собрать, зарегистрировать телефон и что делать, когда что-то пошло не так.

## Что умеет

- вход ключом телефона под Face ID / отпечатком;
- «На подпись» — предложения, ждущие подписи, со счётчиком;
- проверка приказа: экран строится из самого подписываемого объекта, необычные
  получатели и неизвестные поля — красным, подпись — по биометрии;
- новое предложение (сценарий, учение/боевое, пояснение — уровня нет, его задаёт сценарий);
- действующие оповещения и история, кто подписал, **отбой** (оповещение бессрочное — до отбоя);
- продление сеанса кнопкой (доверенность живёт 12 ч);
- push-уведомления: «нужна ваша подпись», «приказ вышел», «предложение отклонено» (§ «Push»).

Внешний вид — как у системных приложений iOS: вкладки внизу («На подпись», «Действуют»,
«История», «Создать»), сгруппированные списки, шторки вместо системных диалогов, светлая
и тёмная тема. На экране проверки кнопка подписи закреплена внизу и включается только
переключателем «Я проверил все поля приказа».


Справочника, контактов и заявок хранителям в приложении нет — это панель дежурного.

## Панель

Приложение — клиент той же панели, что и браузер. Ей нужен вход ключом устройства
(`--org` и `--root-key`) и разрешённые origin'ы приложения — по умолчанию они уже
разрешены (`capacitor://localhost`, `https://localhost`):

```bash
alerting-panel --org acme --root-key <b64u> --server https://alerting.internal
# выключить приложение:
ALERTING_PANEL_APP_ORIGINS= alerting-panel ...
```

Адрес панели должен быть доступен с телефона по **https** с настоящим сертификатом.
Отдельный адрес API приложению не нужен: оно ходит только в панель (`/api/*`), а
панель — к серверу внутри. Панель и API под одним доменом —
`deploy/nginx/alerting-one-domain.conf` (docs/12, §8): в приложение вводится один
адрес, например `https://alert.yamal-media.ru`.

## Сборка

Идентификатор приложения — `me.yamal.alert` (общий для издателя домен yamal.me, как `me.yamal.portal` у портала; к адресу панели отношения не имеет); адреса панели в приложении нет — на первом экране человек вводит тот, что дала его организация (боевой контур, демо-стенд — приложению всё равно, контур определяется адресом). Нужны Node 20+, для iOS — Xcode на macOS, для Android — Android Studio / SDK.

```bash
cd apps/approver
npm install
npm test                 # правила приложения и что оно не должно содержать
npm run build            # www/ — страница, которая уезжает внутрь приложения
npx cap add ios          # уже сделано: ios/ в репозитории (docs/15)
npx cap add android      # уже сделано: android/ в репозитории (docs/16)
npm run sync             # build + cap sync + native-setup
npx cap open ios         # / npx cap open android — подпись сборки и выпуск
```

`native-setup` дописывает то, чего `cap sync` не делает: `NSFaceIDUsageDescription`
в `Info.plist` (без него iOS не даёт Face ID) и `FLAG_SECURE` на Android (экран подписи
не попадает в снимки экрана и в список приложений).

Иконку (обычную, тёмную и tinted для iOS 18, для Android — обычную, круглую и
адаптивную) и заставку (светлую и тёмную) рисует `python3 scripts/icons.py` (Pillow).
Выпуск в App Store, демо-стенд для ревьюера и ответы App Store Connect —
**docs/15-ios-review.md**, выпуск в Google Play — **docs/16-android-release.md**.
Политика конфиденциальности открыта без входа: `<панель>/privacy`, ссылка на неё —
на экранах подключения и входа (оператор и контакт — `ALERTING_ORG_LABEL`,
`ALERTING_PANEL_PRIVACY_CONTACT`).

> ⚠️ **Live update не подключать.** Ни `@capgo/capacitor-updater`, ни `server.url`:
> страница подписи должна быть ровно той, что прошла сборку. Тест
> `test/shipping.test.mjs` это проверяет.

> ⚠️ **Перед выпуском проверить на устройстве**, а не только в эмуляторе: WebCrypto
> Ed25519 в WebView (iOS 17+, Android 11+ со свежим Android System WebView), запрос Face ID без
> кнопки «Ввести пароль», недоступность ключа после добавления отпечатка.

## Регистрация телефона ЛПР

1. ЛПР ставит приложение, вводит адрес панели.
2. «Зарегистрировать этот телефон» → свой идентификатор (`p-010`) → «Создать ключ».
   Публичный ключ и идентификатор ключа можно скопировать кнопкой «Скопировать».
   На Android сразу появится запрос биометрии — ключ защищается ею с первой секунды.
3. Приложение показывает публичный ключ и идентификатор ключа. ЛПР передаёт их
   регистрирующему **лично**; хранители вносят ключ в справочник (`docs/13-custodians.md`).
4. После публикации справочника — «Войти с Face ID».

## Push

### Что приходит и кому

| Событие | Кому |
|---|---|
| новое предложение (и отбой) | всем ЛПР, кроме создавшего: «Нужна ваша подпись» |
| приказ вышел — вторая подпись | всем ЛПР, кроме поставившего её: «Приказ вышел» |
| предложение отклонено | создавшему и подписавшим, кроме отклонившего |

Тап открывает предложение или приказ. Получатели — действующие ЛПР по подписанному
справочнику: ключ отозван — уведомлений нет, какие бы токены ни лежали на сервере.

Уведомление проходит через Apple или Google, и они его читают, поэтому в нём **нет
содержимого приказа** (docs/04-channels.md): ни сценария, ни «учение/боевое», ни
текста — только что произошло и идентификатор. Приказ приложение показывает, как
всегда, из проверенной подписанной нагрузки. Push никогда не мешает приказу: отправка
идёт после ответа, отказ Apple/Google только пишется в журнал.

### Как устроено

Так же, как в приложении helpdesk (`me.yamal.portal`), и по тем же причинам: iOS —
**напрямую в APNs** ключом `.p8` (плагин `@capacitor/push-notifications` на iOS
регистрируется прямо в APNs, Firebase там не нужен и уведомления не идут через
Google), Android — через **FCM**.

| Где | Что |
|---|---|
| `src/alerting/server/mobilepush.py` | транспорт: JWT (ES256 для APNs, RS256 для FCM), HTTP/2 к Apple |
| `src/alerting/server/services/lpr_notify.py` | кому и что; токены, мёртвые удаляются |
| `src/alerting/server/api/push.py` | `/v1/push/tokens`, `/tokens/remove`, `/test` — только свои устройства |
| `apps/approver/src/push.js` | включить, тихо обновить при запуске, снять при выходе, тап |

Токен устройства — секрет (кто им владеет, пишет человеку в шторку): в API наружу
только его хвост, в приложении он живёт в памяти, не в хранилище.

### Настройка

1. **Apple.** Ключ APNs (`.p8`) в Apple Developer → Keys. Ключ — на команду, не на
   приложение: подойдёт тот же, что у helpdesk. Нужны Team ID и Key ID. Право Push
   Notifications в проекте уже есть (`ios/App/App/App.entitlements`), токен плагину
   передаёт `AppDelegate.swift`; в Xcode у App ID `me.yamal.alert` включить
   capability Push Notifications.
2. **Firebase — только для Android.** В проекте Firebase (можно том же, что у
   helpdesk) добавить Android-приложение `me.yamal.alert`, скачать
   `google-services.json` в `apps/approver/android/app/` — **в git он не
   коммитится**. Без него сборка проходит, а push на Android не работает. Сервисный
   аккаунт: Project settings → Service accounts → Generate new private key.
3. **Ключи на сервере.** Docker:
   ```bash
   ./docker/push-keys.sh apns AuthKey_ABC123.p8 <TEAM_ID> <KEY_ID>
   ./docker/push-keys.sh fcm  firebase-service-account.json
   ./docker/up.sh
   ```
   Ключи лежат во внешнем томе `alerting-push-keys` — `up.sh --reset` их не стирает.
   systemd: `ALERTING_APNS_*` и `ALERTING_FCM_*` в `/etc/alerting/alerting.env`
   (`deploy/env/alerting.env.example`), файлы 0600 владельца сервиса. Ключ, которым
   нельзя пользоваться, не даёт серверу стартовать; в журнале при старте —
   `push to the app: ios on, android on`.
4. **Приложение**: пересобрать и выпустить (`npm run sync`, §«Сборка»). В меню
   аккаунта — «Включить уведомления», затем «Проверить уведомления»: тест уходит на все
   телефоны человека, ответ Apple/Google показывается как есть.

Исходящий HTTPS к `api.push.apple.com`, `api.sandbox.push.apple.com`,
`oauth2.googleapis.com`, `fcm.googleapis.com` в `deploy/nftables/alerting-app.nft`
уже разрешён (`tcp dport 443`).

### Где это ломается молча

- **Sandbox и production у APNs.** Сборка из Xcode получает sandbox-токен, TestFlight
  и App Store — production; не тот хост отвечает `BadDeviceToken`. Сервер хранит
  окружение у каждого токена и сам пробует второй хост.
- **Android, пока приложение на экране.** Без `presentationOptions` с `alert` в
  `capacitor.config.json` плагин не показывает уведомление, а только зовёт слушатель.
- **Канал Android.** Без своего канала FCM кладёт уведомления в запасной с важностью
  DEFAULT — они приходят без баннера. Канал `lpr` (HIGH) создаёт `push.js`, каналом по
  умолчанию его назначает манифест; id совпадает в трёх местах, это проверяет
  `test/shipping.test.mjs`.

## Если

| Что видно | Что делать |
|---|---|
| «Набор отпечатков или лиц изменился, ключ недоступен» | Так задумано. «⋯» у ключа → «Удалить ключ с телефона», создать новый, зарегистрировать заново; старый — отозвать в справочнике |
| «Не настроены Face ID или отпечаток» | Настроить биометрию на телефоне — без неё приложение не подписывает |
| «Биометрия заблокирована» | Разблокировать телефон код-паролем, повторить |
| «Приложение — только для ЛПР» | Дежурный работает в панели |
| Телефон потерян | Отозвать ключ: панель → справочник → быстрый отзыв (ADR 0011). Сеансы этого ключа обрываются на следующем запросе |
| Push не приходят | Меню аккаунта → «Проверить уведомления»: ответ по каждому телефону. «APNs/FCM not configured» — на сервере нет ключей (§«Push»); `BadDeviceToken`/`Unregistered` — токен устарел, перезапустить приложение; «уведомления выключены» — разрешить в настройках телефона |
| Сеанс истекает | Плашка «Продлить» над списком или кнопка в меню аккаунта (кружок с инициалами); после перезапуска приложения — снова вход |
