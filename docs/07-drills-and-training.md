# Учения и обучение

Система без регулярных упражнений откажет в нужный день. Этот раздел не формальность.

## 1. Режим

| Периодичность | Что | Что измеряем |
|---|---|---|
| **Ежемесячно** | Технические учения: `drill: true`, малая аудитория, все каналы кроме сирены | доставка по каналам, доля подтверждений, медиана времени до подтверждения |
| **Ежеквартально** | Полные учения: исполнители физически выполняют действия, все каналы включая сирену, обязательно с отбоем | то же плюс время до отбоя |
| **Раз в полгода** | **Состязательные учения**: кто-то намеренно рассылает по реестру фишинговое SMS | сколько людей открыли приложение и сверили слова против того, сколько клюнули |
| **Ежегодно** | Ротация ключей и отзыв с секундомером | время от уведомления до отзыва (цель — менее 60 с) |

Состязательные учения — **единственная честная проверка** того, что раздел про SMS в
[04-channels.md](04-channels.md) работает. Всё остальное проверяет технику; это
проверяет людей.

## 2. Главная метрика

**Медиана времени от `quorum.met` до 90 % подтверждений.**

Растёт от учения к учению — система гниёт: люди отключают уведомления, токены
протухают, телефоны меняются без перерегистрации. Это видно раньше, чем откажет.

Отчёт по каждому учению строится из цепочки аудита:

```bash
alerting-auditor pull   --server http://host:8080 --out chain.json
alerting-auditor report --file chain.json --order-id <uuid>
```

Этот документ предписывал такой отчёт с самого начала, а `report` печатал счётчики
событий и хронологию — медианы в нём не было, и посчитать её из цепочки было нельзя
вообще: у записи `order.dispatched` отсутствовало число получателей, то есть
знаменатель, без которого «90 % подтверждений» не определено. Теперь `order.dispatched`
несёт поле `recipients`, а `report` печатает по каждому приказу время до 90 %, медиану
и «ответило X из Y».

Две оговорки, которые нужно знать, глядя на отчёт:

- **Приказы, разосланные до появления счётчика получателей, печатаются как
  `unknown (chain has no recipient count)`.** Это не ноль и не «мгновенно»: знаменателя
  для них в цепочке нет и не появится, потому что цепочка неизменяема. Сравнивать
  учения имеет смысл начиная с первого, где число есть.
- **Разрешение отметок — целые секунды.** Для медианы в десятки секунд этого хватает, и
  документ с самого начала говорит о метрике в этих единицах.

Те же числа отдаёт `/v1/metricsz` (`alerting_ack_median_seconds`,
`alerting_ack_share_seconds`) — тем же кодом из `alerting.core.metrics`, а не вторым
его переписыванием: две реализации одной метрики разойдутся, и разойдутся молча.

## 3. Карточка исполнителя

Печатная, выдаётся лично под подпись, перевыпускается на каждых квартальных учениях.

```
┌──────────────────────────────────────────────────────┐
│  ОПОВЕЩЕНИЕ — карточка исполнителя                   │
│                                                      │
│  SMS и звонок — НИКОГДА не приказ.                   │
│  Это только сигнал: открой приложение.               │
│                                                      │
│  Три проверки, по порядку:                           │
│    1. Слова из SMS совпали с теми, что в приложении? │
│    2. Приложение говорит «ПОДЛИННЫЙ приказ»?         │
│    3. Кто подписал — видно на экране?                │
│                                                      │
│  Ссылок мы не присылаем. Никогда.                    │
│  Перезванивать — ТОЛЬКО по номеру: +7 ___ ___ __ __  │
│  (номер из сообщения — не наш)                       │
│                                                      │
│  Отбой не отменяет то, что ты видишь своими глазами. │
│  Видишь пожар — «не могу выполнить», указать причину.│
│                                                      │
│  Система не работает: пара «вызов-отзыв» смены,      │
│  повесить трубку, перезвонить по номеру выше.        │
└──────────────────────────────────────────────────────┘
```

## 4. Кодовая книга и словарь

- **Кодовая книга** (`config/scenarios.example.yaml`) — коды сценариев и что делать по
  каждому. Действенная единица — код, а не свободный текст.
- **Персональный ключ побудки** выдаётся в приложение при регистрации.
- **Запасная карточка со сменным кодом** — в запечатанном конверте, меняется
  ежеквартально, невскрытые конверты возвращаются.
- **Словарь** `config/wordlist.ru.txt` — 1024 слова: конкретные, нейтральные
  существительные, без ё (схлопнуто в е, чтобы написанный и произнесённый код не
  разошлись), без близких омофонов.

  Правило: **кодовое слово не должно звучать как указание.** Поэтому в списке города,
  реки, деревья, животные, минералы, инструменты — и нет ничего вроде «тревога» или
  «выходи».

  Замена словаря меняет все коды побудки: перевыпускать карточки вместе с ним.

## 5. Чему учить

Пять пунктов, и всё:

1. SMS и звонок — звонок в дверь, а не сообщение.
2. Три проверки с карточки, в этом порядке.
3. Ссылок не бывает; перезванивать только по напечатанному номеру.
4. Указания — из кода сценария и своей карточки, а не из свободного текста приказа.
5. Отбой не отменяет то, что видно своими глазами.
