# ADR 0002. Сервер на stdlib `sqlite3` с явным SQL, без ORM

**Статус:** принято (для эталонной реализации)

## Контекст

Девять таблиц, среди них журнал только на добавление с триггерами против `UPDATE` и
`DELETE`.

## Решение

Стандартный `sqlite3` и явный SQL в `server/db/repo.py`. Схема — в `schema.sql`.

## Почему

Система, весь смысл которой в прослеживаемости, **не должна прятать свои записи за
маппером**. Рецензент безопасности должен видеть каждую команду, которая касается
`audit_log`, и убедиться, что пути `UPDATE` и `DELETE` просто нет. С ORM это
утверждение доказывается сложнее.

Девять таблиц не требуют ORM. Миграций пока одна.

## Следствия

- `Repo` содержит весь SQL; за его пределами SQL нет.
- В `Repo` **намеренно отсутствуют** методы обновления и удаления для `audit_log`.
- Путь в эксплуатацию: SQLAlchemy + PostgreSQL, когда понадобится несколько узлов.
  Тогда же понадобится вынести счётчик `seq` во внешнюю согласованную последовательность.
- Триггеры — защита от неосторожного администратора, не от root. Настоящая защита —
  цепочка хэшей и внешне опубликованные головы.
