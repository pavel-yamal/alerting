# ADR 0011. Ключ отзыва: быстрый путь, который умеет только отзывать

**Статус:** принято

## Контекст

Цель — отзыв ключа менее чем за 60 секунд от звонка кадровой службы
(docs/02-trust-and-approval.md §4). Справочник ключей подписывает корневой ключ, а он
хранится на машине без сети у двух хранителей. Принести файл, собрать хранителей,
подписать, вернуть, опубликовать — это десятки минут в лучшем случае. Держать
корневой ключ в сети ради скорости нельзя: им же регистрируют ключи, то есть с ним
можно выпустить себе ключ директора.

## Решение

Справочник может назвать **ключи отзыва** (`revokers`: `key_id`, публичный ключ,
метка). Ключ отзыва подписывает **список отзыва** (`type: revocations`, свой домен
подписи `alerting.revocations.v1`): `org_id`, растущая `version`, `signer` и записи
`{key_id, revoked_at, reason}`. Больше он не подписывает ничего.

- Устройства и сервер применяют список поверх справочника: `Directory.with_revocations`.
  Список действует, только если его `signer` назван в текущем справочнике.
- Версии только растут, как у справочника и политики; список накопительный, и сервер
  отказывает списку, из которого выпала запись, пока подписавший его ключ ещё назван.
- Сервер не блокирует публикацию из-за действующих событий, которые отозванный ключ
  подписал, а перечисляет их (`invalidated`): отозвать украденный ключ важнее.
- Корневой ключ прекращает действие ключа отзыва, убрав его из справочника; при этом
  явно решается судьба его списка: перенести в `revoked[]` (`--absorb`) или отбросить
  (`--discard-revocations`, если украли сам ключ отзыва).
- Поле `revokers` отсутствует, а не пусто, в справочниках без него, поэтому уже
  подписанные справочники остаются каноническими байт в байт.

## Последствия

- Отзыв — одна команда дежурного (`alerting-org revoke-now`), секунды; на стенде —
  `./docker/person.sh revoke`.
- Украденный ключ отзыва позволяет только отключать людей. Это отказ в обслуживании,
  а не подделка: каждый отзыв виден в аудите, приказ им не подписать. Лечится
  следующим справочником.
- Ещё один секрет у дежурной смены. Хранится зашифрованным, пароль — у старшего смены;
  смена ключа отзыва — обычная операция хранителей.
- Список отзыва не подписан корнем, поэтому корень по-прежнему видит только свои
  `revoked[]`; при плановой смене ключа отзыва его записи переносятся в справочник.

## Отвергнутые варианты

- **Корневой ключ на рабочем месте дежурного.** Им регистрируют ключи; его кража —
  полная компрометация.
- **Отзыв только на сервере (стоп-лист в базе).** Сервер полудоверенный (ADR 0004):
  устройства продолжали бы засчитывать подписи украденного ключа, а сервер мог бы
  «отозвать» кого угодно незаметно для устройств.
- **Короткоживущие ключи (`valid_until` на сутки) вместо отзыва.** Требует ежедневной
  подписи корнем всех ключей — та же проблема с машиной без сети, только каждый день.
