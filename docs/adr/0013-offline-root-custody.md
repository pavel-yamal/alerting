# ADR 0013. Корневой ключ — у двух хранителей на компьютере без сети, всё через интерфейс

**Статус:** принято

## Контекст

Корневой ключ подписывает справочник ключей и политику; с ним можно выписать себе
ключ директора. На демо-стенде он лежал на сервере (`demo-keys/root-key.SECRET`),
поэтому доступ к серверу означал полный контроль. Инструменты для работы без сети
были (ADR 0011, docs/02 §4), но только в командной строке. Требование заказчика:
всё — через графический интерфейс.

## Решение

1. **Хранилище на двоих** (`alerting.custody`). Ключ шифруется AES-GCM ключом,
   выведенным HKDF из двух независимо растянутых (scrypt) паролей. Открывается только
   обоими; файл без паролей бесполезен и копируется как резервная копия.
2. **Окно хранителей** (`alerting-custodian`): веб-интерфейс на 127.0.0.1 компьютера
   без сети. Создание ключа и карточки, резервная копия, проверка паролей, разбор и
   подпись заявки. Ключ открывается на одну подпись.
3. **Заявка и ответ — файлы.** Панель («Справочник и ключи») собирает заявку:
   текущие подписанные справочник, политика, список отзыва и изменения (добавить,
   вывести, отозвать, ключ отзыва, кодовая книга). Окно хранителей проверяет пакеты
   по своему корню **до показа**, показывает каждое изменение, подписывает следующие
   версии. Панель публикует ответ; сервер проверяет его как обычно.
4. **Перенос** — та же заявка, если пакеты в ней подписаны другим корнем: красная
   плашка, отдельное подтверждение, люди переносятся без перерегистрации, политика
   переподписывается. На сервере его применяет только администратор:
   `alerting-server import-root` (через `docker/rotate-root.sh`) сверяет введённый
   с карточки отпечаток, подписи и версии и пишет `root.rotated` в аудит.
5. **Ключ отзыва смены — в браузере дежурного** (как ключ устройства, ADR 0012):
   «Отозвать сейчас» подписывает следующий список отзыва на месте, без хранителей.

## Последствия

- Доступ к серверу больше не даёт добавить ключ или поднять роль: подписи корня у
  сервера нет.
- Новый человек появляется не мгновенно, а после сеанса хранителей. Отзыв —
  по-прежнему секунды.
- Потеря одного пароля — потеря ключа; лечится переносом на новый ключ без
  перерегистрации людей. Поэтому резервная копия и пароли в разных сейфах.

## Не сделано

- Разделение на N из M хранителей (Шамир) — сейчас ровно два.
- Аппаратный носитель ключа (HSM, смарт-карта).
- Регистрация исполнителей через интерфейс: их приложение пока демо, ключи стенда
  на сервере (docs/12 §9).
