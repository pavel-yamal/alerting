# Выпуск приложения ЛПР в Google Play

Android-сторона `apps/approver` (docs/14, ADR 0016). Для iOS то же самое описано в
docs/15. Демо-стенд для проверяющих один на обе платформы (docs/15, «Демо-стенд для
ревьюера»).

## Что сделано в проекте

| Требование | Где | Проверяет |
|---|---|---|
| Application ID `me.yamal.alert` | `android/app/build.gradle` | `test/shipping.test.mjs` |
| Android 11+ (`minSdkVersion 30`) | `android/variables.gradle` | там же |
| Ключ под строгой биометрией на каждую операцию | плагин `device-vault` | сборка в CI (`android`) |
| Резервные копии и перенос на новый телефон выключены | `AndroidManifest.xml`, `res/xml/data_extraction_rules.xml` | `test/shipping.test.mjs` |
| Снимки экрана запрещены (`FLAG_SECURE`) | `MainActivity.java` (`native-setup`) | там же |
| Свои иконки (адаптивная, круглая), заставка, иконка 512 для Play | `scripts/icons.py` → `res/mipmap-*`, `store/play-icon-512.png` | там же |
| Подпись релиза из файла вне git | `android/keystore.properties` | там же |
| Debug-APK, release AAB и lint собираются | — | задача `android` в `.github/workflows/ci.yml` |

> ⚠️ **Почему Android 11, а не 7.** Начиная с API 30 ключ Keystore создаётся с
> `AUTH_BIOMETRIC_STRONG` на каждую операцию — система пускает к нему только по
> отпечатку или лицу строгого класса. На API 24–29 это делается старым API
> (`setUserAuthenticationValidityDurationSeconds(-1)`), и проверить его здесь было не
> на чем. Служебные телефоны 2026 года — Android 11 и новее; опускать порог можно
> только после проверки старой ветки на живом устройстве.

> ⚠️ **Резервной копии нет намеренно.** Ключ подписи привязан к Keystore и биометрии
> этого телефона; его зашифрованная копия на другом телефоне бесполезна, а
> восстановленный адрес панели с «ключом», которого нет, только путает. Новый телефон
> — новый ключ и новая регистрация, старый ключ отзывают в справочнике.

> ⚠️ **Ed25519 нужен в Android System WebView** (Chromium 113+). WebView обновляется
> через Google Play; на устаревшем приложение при запуске прямо скажет, что не
> поддерживается, и попросит обновить WebView.

## Сборка

Нужны JDK 21, Android SDK (platform 36, build-tools 36), Node 20+.

```bash
cd apps/approver
npm ci && npm test
npm run sync                       # build + cap sync + native-setup
cd android
./gradlew assembleDebug            # app/build/outputs/apk/debug/app-debug.apk — на телефон
./gradlew bundleRelease            # app/build/outputs/bundle/release/app-release.aab — в Play
```

Иконки и заставки, если что-то менялось: `python3 scripts/icons.py` (Pillow).

### Ключ подписи

Google Play подписывает приложение своим ключом (*Play App Signing*), а загрузку —
ключом загрузки, который хранится у публикующего:

```bash
keytool -genkeypair -v -keystore ~/alerting-upload.jks -alias upload \
  -keyalg RSA -keysize 4096 -validity 10000
```

`apps/approver/android/keystore.properties` (в `.gitignore`):

```properties
storeFile=/home/you/alerting-upload.jks
storePassword=…
keyAlias=upload
keyPassword=…
```

Без этого файла `bundleRelease` собирает неподписанный AAB — Play его не примет.
Ключ загрузки в репозиторий, CI и на сервер не кладут.

> ⚠️ **`versionCode` +1 на каждую загрузку** (`android/app/build.gradle`), иначе Play
> её отвергнет. `versionName` — как `MARKETING_VERSION` у iOS.

## Google Play Console

- **Название:** «Оповещение ЛПР»; под иконкой — «Оповещение».
- **Категория:** Бизнес. **Бесплатно**, без рекламы, без покупок.
- **Распространение:** рекомендуется закрытое — *Managed Google Play* (частное
  приложение для организации) или закрытое тестирование по списку почт. Публичное
  размещение допустимо, если в описании сказано, что нужна учётная запись организации.
- **Политика конфиденциальности:** `https://<панель>/privacy` (для проверки —
  страница демо-стенда).
- **Доступ к приложению (App access):** «Часть функций доступна по особому доступу»,
  инструкция — та же, что Review notes в docs/15: адрес демо-стенда, «Зарегистрировать
  этот телефон» → «Создать ключ» → «Войти» → учение TEST.PING. Учётных данных нет,
  только адрес; на устройстве проверяющего должен быть настроен отпечаток или лицо.
- **Безопасность данных (Data safety):**
  - собирается: *Личная информация → Имя* и *Идентификаторы пользователя* (ФИО и
    идентификатор из справочника организации), *Другой пользовательский контент*
    (приказы, подписи) — для работы приложения, не передаётся третьим лицам;
  - данные шифруются при передаче (HTTPS);
  - удаление: ключ — кнопкой «Удалить ключ»; запись в справочнике и журнал — по
    обращению к организации-оператору (контакт на странице `/privacy`);
  - биометрию приложение **не собирает** — её проверяет система.
- **Целевая аудитория:** 18+, не для детей. **Новостное приложение:** нет.
- **Разрешения:** `INTERNET`, `USE_BIOMETRIC` (Play может спросить про биометрию —
  ответ: защита ключа подписи, данные не покидают устройство).

## Перед выпуском — на живом телефоне

Здесь сборка проверена компиляцией и lint; эмулятора не было. На телефоне проверить:

1. Регистрация на демо-стенде: при «Создать ключ» сразу запрос биометрии.
2. Вход и подпись учения — каждый раз запрос отпечатка/лица, без варианта «PIN».
3. Добавить новый отпечаток → ключ недействителен, приложение говорит об этом.
4. Снимок экрана на карточке приказа не делается, в списке приложений — пустая карточка.
5. Тёмная тема, поворот, планшет — вёрстка не ломается.
